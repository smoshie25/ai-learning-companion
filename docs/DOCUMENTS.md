# Document Intelligence & Study Assistant

Open **Study Documents** and import PDF, DOCX, TXT, or Markdown using the native file picker. Import is entirely local. The renderer receives document IDs and extracted content, not filesystem paths or arbitrary file/network access. No original binary is uploaded to OpenAI or copied into the app's bundle. Extracted text, analysis, Q&A and study progress live in SQLite migration 8.

## Guided multi-chapter workflow

1. Run `npm run build` and `npm start`. Import [`demo/study-material.md`](../demo/study-material.md), a four-chapter database engineering guide.
2. Inspect **Source & sections**. Headings and original line numbers are available without an API key. Choose a PDF to see physical page citations, or DOCX to see heading/paragraph citations.
3. Save your OpenAI API key in Settings and select an OpenAI configuration. Check the document-content consent box, then **Analyze document**. This authorizes the requested batch of section and hierarchical summary calls; API usage can be billed. Unchecking the box prevents new requests. To stop an already authorized batch, use **Pause analysis**; its current provider request can finish first.
4. Watch the completed-section count and the chapter/executive synthesis status. Source sections are saved as each finishes. A failed section shows an error and can be retried independently; **Retry failed sections** keeps all successful results. Interrupted work is paused on restart and requires explicit consent/resume. Completed chapter checkpoints survive a hierarchy retry.
5. Inspect the executive and chapter summaries. Open a source citation to see the exact highlighted text and its original page or section. In **Study tools**, explore concepts, definitions, suggested priorities, practice questions and flashcards. Expand a card to reveal its answer; mark it reviewed and mark the section studied. These local progress changes require no API call and survive restart.
6. In **Ask the document**, ask “What does atomicity mean for a transaction?” Local lexical retrieval selects at most five source chunks; only these and the question are sent to OpenAI. The answer must carry exact source evidence. Ask “How do interstellar spacecraft navigate?” to exercise an honest unsupported outcome. Missing facts are not filled in from general model knowledge.
7. In **Study tools**, select up to eight sections and optional concepts from the current selected section. Set a learning goal, daily budget and optional deadline, then **Propose document study plan**. Review opens the new plan directly in **Learning Planner → Personalized plans**. Source evidence is preserved by task key. Approval, editing, dependencies, completion and practice assessment use the existing planner lifecycle; generation never approves tasks automatically.
8. Configure a role, experience, interview type, duration and language, then **Start document mock interview**. Questions and private interviewer reference answers are generated from the selected source sections with exact citations. Open the new interview directly, answer, end and request existing rubric feedback. Document references support the question bank; candidate-answer excerpts remain the only evidence for scores. The document flow starts in text mode; pause the interview and resume with separate microphone consent for voice. Patient semantic voice turn detection remains in effect.
9. Restart the app and inspect saved summaries, Q&A, studied sections, reviewed cards, plan references and interview source context. Opening a saved document does not grant new transmission consent.

The native automated journey follows these steps with actual local extraction and mocked AI; it never uses a real key, microphone or billed provider call. `npm test` also checks malformed evidence, unsupported answers, chunk limits, hierarchy reduction, retry isolation, cancellation/recovery, actual PDF/DOCX files and persistence across restart. Mock output proves lifecycle and citation invariants, not the quality of live model interpretations. Test real materials with your own consent and configuration.

## Extraction and source limits

- Files: non-empty, up to **20 MB**; extracted text up to **1.5 million characters**, **400 chunks** of at most **4,500 characters**, and PDFs up to **500 pages**. Oversized inputs are rejected with instructions to split chapters; text is not silently truncated into an apparently complete document.
- Parsing runs in a worker with a 45-second timeout and bounded V8 heap. DOCX reads only document/style XML; oversized entries, excessive entry counts and XML entity declarations are rejected. No external relationships, macros, images or embedded resources are executed or fetched.
- PDF.js extracts text in page order, retains outline headings where available and recognizes some chapter labels. Columns, equations, tables and font encodings can affect reading order. Images/scanned pages are not OCR'd; empty pages are disclosed, and a fully textless PDF cannot be analyzed. Password-protected/corrupt PDFs need a readable local export.
- DOCX retains paragraph text, standard/custom heading styles and table-cell text in XML order. Word's rendered pagination is not reconstructed. DOCX references use paragraph numbers; headers/footers, footnotes, comments, images and tracked-change semantics are not reconstructed.
- TXT and Markdown support UTF-8 or BOM-marked UTF-16. Heading hierarchy, code/text content and line locations are retained; Markdown is shown as text, not executed or rendered as arbitrary HTML.
- Chunk boundaries preserve headings/pages and local source substrings. Synthesized citations must retain **exact** existing chunk ID/quote pairs. The source viewer maps citation IDs back to trusted page/heading metadata instead of accepting AI-generated citation locations or URLs.

## Analysis, consent and reliability

Section analysis yields summaries, concepts/focus areas, definitions, recommended priorities, practice questions and flashcards. Bounded groups of grounded section points are reduced into chapter summaries, then recursively reduced into an executive summary. Each reduction produces fewer points than its batch, so long inputs cannot trigger a non-converging summary loop. Outputs use the existing official Responses SDK, strict Zod schemas, `store: false`, centralized retry/timeout policy, redaction and safe usage tracking. There is no cloud file store, vector database or backend server.

Every summary, definition, priority, practice answer, flashcard, Q&A answer, study task and question-bank item requires exact source quotes from the supplied selection. Citation validation rejects unknown IDs, fabricated quotes and new quotations introduced during hierarchy reduction. Quote presence establishes provenance, **not guaranteed semantic entailment**; review the highlighted text before relying on an AI interpretation. Suggested activities are not source assignments. Unsupported Q&A returns a clear source-limited message. Lexical retrieval can miss synonyms, so rephrase using the document's terms or inspect the source directly.

One document AI operation runs at a time. Credential changes are blocked while it is active. Pause, navigation reload and exit stop further batch requests; an in-flight request may finish. No raw exceptions, provider objects or credentials are exposed. Normal in-app navigation can leave an explicitly approved batch running; return to Study Documents to see its progress or pause it. Leaving the screen clears its consent checkbox for new operations, while the already authorized batch remains explicit until paused/completed.

Deleting a local document removes its extracted text, analysis, Q&A and progress, and leaves the original file untouched. Documents referenced by non-rejected plans or saved material-based interviews cannot currently be deleted, preserving evidence. The MVP has no interview-history deletion tool; keep such source documents or use an isolated profile for temporary material. SQLite learner/document data is not encrypted at rest. Original files are not retained; citations refer to the locally extracted snapshot and saved display filename, so replacing a file requires a new import. Identical content hashes reuse the existing document without overwriting progress.

References: [PDF.js](https://github.com/mozilla/pdf.js), [fflate](https://github.com/101arrowz/fflate), [fast-xml-parser](https://github.com/NaturalIntelligence/fast-xml-parser), and [OpenAI structured Responses outputs](https://developers.openai.com/api/docs/guides/structured-outputs).

PDF citations tolerate whitespace-only layout differences, then save the exact original source span. Changed words, punctuation, case, and invented or cross-section excerpts remain rejected. Failed-section reasons appear in the overview.

Document Responses now use a main-generated excerpt catalog: the provider returns enum-constrained citation IDs, and main resolves them to exact original chunk IDs and source text. This applies to section analysis, hierarchical synthesis, Q&A, plans, and interview question banks. Unknown IDs or provider-supplied quotations are rejected. Existing stored analyses and references remain readable; failed sections can be retried without reimport. Source presence still requires learners to check whether an interpretation is justified.
